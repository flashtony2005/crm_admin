阶段 1：订阅状态机

让 Stripe 的订阅事件真正驱动会员有效期 · admin（私有化创作者变现站）· 2026-09-28 · 迁移 0017_subscriptions / 0018_subscription_granted_expiry
一句话结论：订阅事件此前统一落 pending_apply —— 钱收了，什么也不做。 现在四类事件由状态机真处理：建本地订阅镜像、按周期终点决定是否发货、把订阅收入记进 orders，并由调度器每分钟兜底到期降级。

过程中挖出三条缺陷，其中一条是 永久会员： 「订阅结束后该不该把会员降级」原本用 members.plan_expires_at 判断 「他是否另有来源」，可那个值恰恰就是这个订阅自己写进去的 —— 同义反复， 于是任何订阅结束后都永不降级。它比历史上的「空到期 = 永久会员」更隐蔽： members 表自身完全自洽，只有拿订阅行去对才看得出来。

一、整条链路

四条事件入口 → 同一套状态机；调度器兜底走的是同一个 apply_row

二、核心不变量：判据是「周期终点」，不是「收到哪个事件」

这一条决定了其余一切。当初把四类事件一起丢进 pending_apply，本质上是因为 没有这条判据 —— 不知道 customer.subscription.deleted 到底该不该降级。

Stripe 状态周期未过周期已过为什么
active / trialing有效失效续费事件丢了也不能白送
canceled有效失效期末取消：用户已付到期末，提前停服等于吞掉他付过的那段
past_due有效失效Stripe 正在重试扣款（卡过期最常见），立刻断供会误伤刚换卡的用户

不认识的状态一律失效反过来意味着 Stripe 新增一个状态就能白送会员
乱序防护：Stripe 不保证事件顺序（重投与并发投递都会乱序）。订阅行记 last_event_at，只接受更晚的事件 —— 否则旧的 customer.subscription.updated 后到会把刚续费的周期覆盖回去， 表现为「刚续完费又变回过期」。
两个边界都不许「丢事件」：本地无时间戳时任何事件都算新；事件体缺 created 时不做判定（不能因为一个可选字段缺失就丢掉一次真实扣款）。

三、挖出的三个缺陷

1. 永久会员 降级判据是同义反复

订阅结束时不能无条件把会员降回 free —— 他的有效期可能另有来源 （线下人工开通、积分兑换、兑码）。所以最初写的是「若 members.plan_expires_at 仍大于 now，说明另有来源，保留」。

问题是：那个值恰恰就是这个订阅 Grant 时写进去的。只要订阅曾经发过货， plan_expires_at 就必然大于 now（否则它早就该降级了）。 于是判据恒为真 → 永不降级 → 会员一直有效下去。

修法是在订阅行上增加 granted_expiry（本订阅最后写进会员的到期时间）， 判据改为 相等：

granted == members.plan_expires_at
  ⇔ 自那次 Grant 之后，没有别的来源改写过它
  ⇔ 降级是安全的

一旦人工开通 / 兑码 / 另一个订阅后来写过，两者不再相等 → 保留。 空串的语义是「本订阅从未授予过」，此时不由它来决定降级。

这条缺陷有个更难察觉的地方：改动前 cargo test 只挂了 3 条， 而 subscription_end_does_not_clobber_another_grant（「另有来源必须保留」） 是"通过"的 —— 它被错误实现"蒙对"了。两个语义完全相反的用例， 在错误实现下竟然同时"成立"，说明判据本身没有区分力。

2. 既有假安全 .never 哨兵对 Owner 无效

orders / points_ledger / subscriptions 这类审计表 用 perm_prefix.never 表达了「不可写」的意图。但权限匹配里 Owner 的通配 "*" 命中一切，.never 只是个普通权限码 —— 所以 从来就没拦住过任何人，Owner 可以直接 POST 进去改账目。

现在判定放在权限校验之前（deny_if_audit_only），与角色无关， 返 403 并说明原因。测试 audit_only_tables_reject_writes_even_for_owner 钉死。

3. 测试自身的构造与语义矛盾

expire_due_demotes_without_any_webhook 想表达「此前发过货、只是终结事件丢了」， 却把会员到期时间写成了 now + 100 天，而订阅周期是 now - 1 天。 两者不一致，在数据上恰好等价于「另有来源给了更晚的有效期」 —— 按正确语义就应该保留，于是断言「必须降级」必然失败。

真实世界里订阅周期已过时，它 Grant 进去的那个值也必然已过，两者相等。测试已按此修正。

六、遗留

  • 退款与争议没接：charge.refunded / charge.dispute.created 未处理 —— 周期中途退款时会员不会立即失效，要等到周期末由兜底降级收口。 这是保守方向（不会多发服务），但与财务口径不一致。
  • 对账没有主动校验：本地订阅与 Stripe 的一致性目前只靠「到期兜底」保底， 没有「定时拉取 Stripe 订阅列表比对并补偿漏事件」的通路。
  • 订阅记录页是只读全局视图：不能按会员下钻（要走会员抽屉）；列表也未 join 套餐名与会员邮箱，只有原始 id。
  • 观察项（非本轮引入）：web/public 只有 favicon.svg、 没有 favicon.ico，也没写 <link rel="icon">， 浏览器每次会自动请求 /favicon.ico 得 404。一行 link 即可消除。
