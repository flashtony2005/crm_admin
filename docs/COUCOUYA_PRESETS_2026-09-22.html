结论

「多做几个模板」如果按老路子做（每个模板一份独立代码），是纯粹的负债——付费墙、详情页、SEO 每加一个模板都要重做一遍。正解是抄 WordPress 真正赢的那套： 内核极简 + 预设丰富。本轮把 CouCouYa 的首页外观拆成两个正交维度：5 套版式预设 × 10 档风格变体 = 50 种组合，代码只有一份。

二、关键洞察：赢的不是「设计」，是「架构」

两个榜单的第一名在视觉上几乎完全相反：

  • Hello Elementor（装机量第一，12.9%）几乎是零设计的空壳——它的卖点是不和页面构建器打架；
  • Twenty Twenty-Four（WP.com 第一，9.78%）是自带样式变体的块主题——开箱就是一整套设计。

它们赢法完全一致：内核极简 + 预设丰富。Astra / GeneratePress / Blocksy / Kadence 全是同一个套路——不是一个主题解决所有场景，而是「一个内核 + 一堆 starter template / style variation」。

还有一个信号印证这点：页面构建器份额一年内从 56% 掉到 43%，而原生块编辑器从低位涨到 18%。用户要的是开箱即用的设计预设，不是无限可配置的构建器。

四、落地：三层改造

L1 · 风格变体 4 → 10 档

等价于 WordPress 的 Global Styles / theme.json：一组语义变量，组件完全不感知。除配色外，档位还覆盖 --font-display（衬线与否）与 --radius（方圆气质）—— 这样"换风格"才不只是换色。

等价于 WordPress 的 block pattern / template：同一批组件，换个顺序与变体就是另一个"主题"。预设决定排布，风格决定配色，两者正交可自由组合。

组件只认「变体」，不认「预设」。这是关键解耦——新增一套预设只是往 PRESETS 加一条声明，不需要改任何组件：

Hero 变体：default | wide | minimal | compact Writing 变体：grid（三列卡片）| list（图文横排单列）| masonry（两列大图） sidebar 骨架额外渲染侧栏模块（Aside.tsx）： subscribe 订阅位 · recent 最近更新 · toc 本页目录 ↑ 订阅位是这个骨架的主要意义：把转化入口常驻在每一屏，而不是埋在页面底部

L3 · 后台切换

完整复刻既有的 homeTheme 链路：site_settings KV → /api/public/site 的 homePreset → 前端应用。后台「站点外观」多了「主页版式」区块，每套预设配一张骨架缩略图。

site_settings.home_preset (KV, 权威) ↓ site.rs::site_value GET /api/public/site → { homeTheme, homePreset, homeTemplate, mainPort, ... } ↓ ↓ coucouya/src/App.tsx admin 站点外观「主页版式」选择器 getPreset(id) → 区块序列 /w/templates/manifest.json → items[].presets[] (目录性信息)

五、风格优先级链

theme = 用户手选(localStorage) ?? 后台「主页风格」指定 ?? 当前预设建议
  • 用户手选优先，且跨预设保留 —— 用户选过的风格不该被换预设冲掉；
  • 后台那一档留空（''）表示"不指定"，让位给预设建议；填了具体值则强制覆盖；
  • 只有真的手选过才写 localStorage，「跟随版式预设」会真删键（否则下次加载又把手选值读回来）。

八、以后怎么加

加一套版式预设

只改 1 个文件：

  • coucouya/src/presets.ts 的 PRESETS 加一条声明（区块序列 + 骨架 + 建议风格 + 侧栏模块）

只有想加全新布局形态（如三列瀑布流）时，才需要给对应组件加一个变体。

加一档风格变体

要同步 3 处（都是清单，不是逻辑）：

  • coucouya/src/index.css — 加一组 [data-theme='xxx'] { --bg: … }
  • coucouya/src/themes.ts — THEMES 加一项（id / 名称 / 分组 / 三色）
  • admin/web/src/routes/site-appearance.tsx — HOME_THEMES 加一项，后台才选得到

九、遗留与建议

本轮已补齐（2026-09-22 第五轮）：

  • ① home_preset 白名单校验 —— 已做。新增后端单一目录 server/src/presets.rs；site.rs::update_site 遇到非空且非法的值即返回 400 并列出可选值（实测 "bogus" → 400 且不落库，合法值正常生效）。
  • ② 预设清单三处副本 —— 已收敛。目录元信息以 server/src/presets.rs 为单一权威：templates.rs 的清单由 presets::ids() 派生；后台 UI 改从 /api/public/site 的 homePresets 拉取（只留 FALLBACK_HOME_PRESETS 离线兜底）；模板卡的预设显示串同样改为派生。presets.ts 退为「版式实现」权威。新增一档预设 = 改两处。
  • ③ about 区块的「1111」—— 已清。顺带修掉 hero.bio 里同源的 可可鸭ga 残留，对齐 content/home.json 的正式文案，并已通过 /api/public/home 复验。

仍然遗留：
