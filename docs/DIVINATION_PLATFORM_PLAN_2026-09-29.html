把 admin 改造成「命理咨询平台」

基于现有代码库的架构盘点 · 内容补齐 · 引流 · 变现 · 2026-09-29 · 对象：F:\project\admin（Rust Axum + sea-orm / React）· 主页 F:\project\coucouya
先说结论（四问四答）
① 架构最大的不足
不缺 CMS，缺「领域层」。现在的 admin 是一个成熟的内容 + 会员变现站， 但完全没有排盘引擎、命盘对象、咨询/预约/会话、分账结算这四个命理平台的核心件。 另外有三处是硬伤：无行级授权（命理师能看全站订单）、 出生信息属敏感个人信息却明文入库、前台是纯客户端渲染（SEO 抓不到）。
② 内容要补什么
内容形态要从「文章」切换到「程序化生成的结构化页面」。 命理类的流量 90% 来自工具型长尾页（排盘结果页 / 黄历 / 生肖星座日运 / 术语词典）， 而不是博客文章。现有 articles 表（当前仅 9 篇，1 个空壳已发布） 撑不起这个量级，需要「模板 + 数据 → 静态页」的生成能力。
③ 怎么引流
抖音/小红书/微信小程序对「算命」是明令禁止的，所以正面渠道走不通。 可行的是三条：① SEO 工具页矩阵（最大的免费流量池）； ② 知识科普型短视频（去预测化，只讲「怎么看」不讲「准不准」）； ③ 命理师自带流量入驻（B2B2C，每个从业者就是一个渠道）。 项目已建好的归因链路（访客 → 注册 → 收入）可直接复用做渠道 ROI。
④ 怎么收费
最现实的收款通道，项目已经有了——orders 的 channel=manual 线下人工开通（命理类正规商户号极易被拒/清退，扫码转账 + 后台确认反而是主力）。 收费阶梯：免费排盘 → AI 报告 ¥19.9 → 人工精批 ¥98-198（抽佣 20-30%） → 1v1 咨询 ¥299-999（抽佣 25-30%）→ 会员订阅 ¥18/月。 缺口是 退款/争议和给命理师的分账提现——这两个不补，规模一大必爆。
一句话判断：这个项目离「能上线跑起来」只差两个月的工程量， 但离「合规地活着」差一个定位决策——见下一节。技术不是瓶颈，定位才是。

一、前置判断：这不是「算命平台」

这一节必须先讲，因为它直接决定了后面所有架构选型。如果按「算命平台」做，你会死在审核和支付上。

监管现实（2026 年现行规则）

主体 / 渠道现行规则对本项目的影响
微信小程序 明确驳回理由原文：「涉及算卜算运势、算命、付费取名等内容，属于平台未允许内容，请移除相关内容或功能后再重新提交」。 连「只是排盘工具、没有算命付费」的版本也被判违规；把文案改成「排盘/分析/易学文化交流」仍被拒，因为审核员会逐页看内容，页面里的「吉凶」「宜忌」「用神」「格局」照样触发。 小程序路线基本封死
微信支付 虚拟商品购买必须接入官方「小程序虚拟支付」；而小程序本身不允许命理类目 → 形成死结。 正规商户号不可依赖
抖音 通报处置「玄学大师」人设、隐晦表达提供「转运」「消灾」「改命」服务并导流站外，821 个账号被回收直播权限/禁言/封禁。电商规则把「塔罗、八字、择吉」统一归为「违反公序良俗、封建迷信类的商品及服务」。 短视频只做科普，不做服务
公安 / 网信 「净网 2026」专项行动：直播连线算命宣扬封建迷信，约谈主播并责令删除全部相关视频与直播回放，宣讲《互联网信息服务管理办法》《网络信息内容生态治理规定》《网络主播行为规范》。 真人出镜直播算命是法律风险
行业共识 塔罗类内容被公开定性为「监管重点」：禁止承诺「百分百准确/必复合/改运」，禁止恐吓式收割，禁止面向未成年人，仅可作为趣味文化 / 心理娱乐展示。 必须做成「娱乐参考」

三条路线，选一条

路线 A合规工具 + 文化社区
对外一句话：「东方传统文化与个人成长参考工具」
做什么：排盘工具、命理知识、术语百科、社区讨论、AI 生成的文化解读报告（不称"算命"）
不做：真人收费断财运/婚姻、改命、消灾
✓ 可长期活 ｜转化率最低、客单价最低，但唯一能买量、能上应用商店、能开对公账户的路
路线 B · 推荐命理师变现基础设施（B2B2C）
对外一句话：「传统文化从业者的内容与交易工具」
做什么：平台提供排盘引擎 + 开号 + 内容 + 预约 + 收款 + 分账， 从业者自己交付服务、自己承担话术责任；平台收工具费 / 交易佣金
不做：平台自己出面承诺预测结果
✓ 与现有项目基因完全吻合 ｜admin 的定位本来就是「创作者变现站」，这一步是顺延不是转型
路线 C纯自营高客单（现金最快）
对外一句话：不对外，靠私域
做什么：公域只做科普引流 → 私域成交 ¥299-2999
不做：不做公开平台、不做品牌
△ 来钱快、天花板低、随时被封 ｜可作为路线 B 的冷启动现金流，但不该是终局
推荐组合：以 B 为主干，A 做流量外壳，C 做冷启动现金流。 即：对外是「传统文化工具站」（A 的壳）→ 供给端是「命理师入驻变现」（B 的骨）→ 流量端先靠私域高客单养现金流（C 的血）。这三者共用同一套排盘引擎与订单系统，架构上不冲突。
必须现在就定的命名红线（贯穿代码、文案、商品名、免责声明）：
  • 禁用词：算命、占卜、预测、包准、灵验、改命、转运、消灾、化解、必复合、开光、符咒、法事
  • 替换词：排盘 / 命盘解读 / 传统文化参考 / 个人成长报告 / 性格与节奏分析 / 电子文档
  • 每一份内容、每一份报告、每一次咨询对话窗口下方，强制注入「本内容属传统文化娱乐参考，不构成任何决策建议，请理性看待」
  • 未成年人不得下单：下单前必须有年龄确认，后端要能拦截（不是前端隐藏按钮）
这些词应该做成一张后端可维护的黑名单表，在文章正文、评论、咨询消息、命理师档案四处写入前拦截 —— 既是被平台封号的红线，也是被认定「虚假宣传/诈骗」的法律红线。

2.3 十一条具体不足，按严重度排

等级不足为什么是问题 / 怎么补
P0 没有排盘引擎 这是命理平台的发动机，现在是零。后端 server/src 无任何算法代码。
落地选型（已核实可用）：
· tyme4rs（6tail 官方 Rust 版，MIT）—— 公历/农历/干支/节气/生肖/月相，节气算法引自寿星天文历，是 Lunar 的升级版，直接 cargo add 可用；
· lunar_rust（lunar-python 的 Rust 移植，MIT）—— 八字、十神、纳音、彭祖百忌、每日宜忌、吉神方位、冲煞、星宿，黄历页面的数据源基本齐了；
· 紫微斗数：iztro（TypeScript，MIT，4.2k star）是目前事实标准，但只有 JS 实现，Rust 侧要么移植要么起 Node sidecar。
· 真太阳时校正：需要「城市 → 经纬度」坐标表（现有项目完全没有地理数据），这是自建项。
架构铁律：引擎必须是确定性纯函数 compute(input) -> ChartProfile，输入输出可序列化、可快照、可单测；绝不允许把"流派配置"做成全局可变状态（见下方警告框）。
P0 「命盘」不是一等对象 现在整个系统只有一个内容实体 articles（当前库里 9 篇，其中 5 篇 published、4 篇 draft，1 个 pillar 是 97 字的空壳）。 但命理平台的核心数据是命盘——它既不是文章也不是订单，是「一个人 + 一次计算 + 一份可复现结果」。
必须新建 chart_profiles：存出生信息（精确到分钟的出生时间 + 出生地经纬度）、性别、历法类型、引擎版本、流派配置、计算结果快照（JSON）、owner_member_id。
为什么必须存快照而不是每次重算：引擎升级或流派变更会改变结果（真实案例见下），不存快照就解释不了「为什么昨天的报告和今天不一样」，这是信任崩塌级的客诉。
P0 无行级授权（数据越权） 现在权限是全局的：3 个写死角色（owner/editor/viewer），单角色，无 role_permission 表， 所有校验都是「你有没有这个权限码」，没有「这条数据是不是你的」。
命理平台里每个命理师都带着客户的高敏出生信息，一旦开放入驻，A 命理师能查全站订单和会员资料 —— 这是数据泄露级事故，不是体验问题。
必须补：resources.rs 的 TableDef 增加 owner_column，网关层自动注入 WHERE owner_id = ?（owner 角色豁免）；新建 role_permission 表支持自定义角色 + 多角色（代码注释里已写「Phase 3 才落」，现在得提前）。
P0 出生信息 = 敏感个人信息，现在明文裸奔 出生时间 + 出生地点组合起来可以唯一指向一个人，属《个人信息保护法》口径下的敏感个人信息：需要单独同意、加密存储、最小必要、支持删除。
现状：SQLite 明文列，无字段级加密，无「导出我的数据 / 删除我的数据」通路（只有 revoke-sessions）。
更严重的是上传：POST /api/upload 存本地 uploads/，然后 nest_service("/uploads") 裸伺服、无鉴权——用户上传的手相/面相照片是公开可访问的 URL。这个必须改：私有文件走带签名的短时 URL。
P0 没有退款 / 争议通路 代码里明确未接 charge.refunded / charge.dispute.created。
命理咨询是退款率天然极高的品类（用户主观判断「不准」就会要求退，行业的公开教训就是「承诺准确率＝把自己逼进死胡同」）。没有退款状态机和争议留痕，规模一大必定演变成投诉/举报/封号。
必须补：订单状态机加 refunding / refunded / disputed；disputes 表；超时未交付自动退；退款原因分类（用于反哺内容质量）。
P0 前台是纯客户端渲染，SEO 抓不到 这是引流侧最大的架构债。coucouya 是 Vite 构建的 React SPA，由后端 GET /t/{slug} 伺服一份静态 index.html，所有内容靠浏览器执行 JS 后渲染。
对 Google 尚可（会执行 JS），对百度/搜狗/头条搜索/微信搜一搜——命理流量的主战场——几乎不可抓。
必须补：工具页与服务端渲染/构建期预渲染（几万个静态页），或者把「排盘结果页 / 词典页 / 日运页」做成后端直出 HTML。现有 articles 的服务端直读 DB 模式（/read/*）可以借鉴，但那个也是 SPA 兜底，要重新做。
P0 没有内容风控黑名单 现在有评论审核（status）和举报，但没有词级拦截。命理类内容的「改命、消灾、必复合、包准」这些词，既是平台封号红线也是法律红线（虚假宣传/诈骗）。
而且风险面不止文章：评论、咨询消息、命理师档案、服务标题、报告正文五处都要拦。
必须补：banned_terms 表（后台可维护）+ 统一校验入口，在写入前拒绝并点名（对齐项目已有的「Col::ReadOnly 写入即 400 点名，不静默」风格）。另需年龄门槛拦截（后端强制，不是前端隐藏按钮）。
P1 交易模型撑不住服务类订单 orders.biz_type 目前只有 points_recharge | plan，channel 只有 wechat | manual（库里 13 单全是 plan，¥18/¥180 两档）。
需要扩到 report | service | booking | plan | points_recharge，并补「按次 / 按时长 / 按人」三种计价方式与改期/取消的计费规则。
P1 没有分账与结算 B2B2C 模式的命脉：平台代收 → 抽佣 → 给命理师结算 → 提现审批 → 个税代扣。
现状零概念。建议 MVP 不做自动分账（合规和资金池都麻烦），先做「命理师自己在平台内发起的结算申请 + 后台人工审批打款」，把资金流留在银行侧，平台只记录账。
P1 没有全文检索 全局无 FTS5，articles.tags 只有 LIKE '%x%' 子串匹配（public_api.rs:213）。
「术语词典 + 案例库 + 命理师」这三类内容检索是刚需。libsqlite3-sys 的 FTS5 绑定符号已经链进来了但从未调用，启用成本很低。
P1 角色体系不足以支撑入驻生态 需要新增 master（命理师：只管自己的档案/订单/内容）、moderator（内容审核，玄学类审核压力大）、finance（结算审批）、ops。
后端 perm.rs 21 条权限码 ↔ 前端 config/permissions.ts 约 83 条 双向镜像，新增必须两边同改（这是项目既有硬规则，漏一边就会出现「后端拒绝但前端没按钮」或反过来）。

顺手要清的技术债（趁这次一起处理）

  • 12 张 0003 遗留表还在库里且有数据（sites/contents/contexts/users 非空、无消费方）。库共有 58 张表，而 resources.rs 白名单只有 28 张——中间的差值就是这批遗留物。别当它们是空的，建新表前先确认命名不冲突。
  • tags 表的建表语句不在 db.rs::MIGRATIONS 里，而散落在 server/migrations/*.sql（需手工执行）。这是 schema 漂移点，本次新建表必须统一收拢进 MIGRATIONS。
  • tenant 硬编码为 t_demo（main.rs:382）。若要做「平台 vs 入驻命理师」的多主体隔离，需要从 JWT 动态解析——但建议先不碰，用行级授权解决，改动面小得多。
  • 死依赖：cytoscape / chart.js / @xyflow/react 在 package.json 里声明了但源码零引用（实际图表用自研 SVG）。
  • 无日期库（全用原生 Date）。命理平台对日期极其敏感（时区、真太阳时、农历边界），必须引入 date-fns/dayjs 级别的日期基建，别再用原生 Date 硬算。
一个真实踩坑，建议写进架构文档当铁律：紫微斗数库的"版本就是流派"。
iztro 在 2.5.0 → 2.6.0 之间悄悄改了年分界默认值：2.5.0 默认按「立春」分年，2.6.0 默认按「正月初一」分年。 同一个人、同一个生日、同一个库，换个版本就排出不同的盘，而这个变更没有写在显眼处。
市面上大量工具建在这个库上、升级节奏各不相同 —— 所以「两个网站排出来不一样」的原因，可能只是其中一个没升级。
推论：你的 divination-core 必须做到三件事—— ① 引擎版本号随盘落库并随盘返回；② 流派/分界规则是显式参数（不可变的配置对象逐层传递），不是模块级全局变量； ③ 每张盘可复现（同输入 + 同版本 + 同流派 → 逐字节相同的输出），并用快照测试钉死。
否则你的用户会拿竞品的盘来质问你 —— 而你说不清谁对。

三、内容上要补什么

最关键的一个认知转变：命理平台的内容主体不是「文章」，是「程序化生成的结构化页面」。 用户搜的是「1990 年属马 2026 年运势」「八字排盘」「今天宜忌」，这些是数据驱动的工具页，不是人写的博客。 现有 articles 表（9 篇）撑不起这个形态，需要新建「模板 + 数据 → 静态页」的生成能力。

3.1 四类内容，各司其职

Ⅰ 工具型拉新主力 · 占目标页数 70%

唯一能靠自然搜索获客的内容。每个结果页都是一个可索引的独立 URL。

  • 在线排盘：八字 / 紫微 / 六爻 / 塔罗 —— 每个盘一个 URL（可带 ?k=hash 或 /chart/{id}）
  • 老黄历：每日宜忌、吉神方位、冲煞、纳音 —— tyme4rs+lunar_rust 直接供数
  • 生肖运势：12 生肖 × 12 月 × 流年 = 可覆盖上千长尾词
  • 星座运势：12 星座 × 日/周/月 —— 同一个数据底池换模板
  • 术语词典：十天干、十二地支、十神、五行、纳音、神煞、宫位、四化…… 200-400 条，每条一页
  • 吉日查询：嫁娶 / 搬家 / 开业 / 出行 —— 商业搜索量大、季节性强
  • 起名 / 测名 / 合婚：标准品工具，转化路径最短
Ⅱ 知识型建立权威 · 占 15%

建立「专业」认知，是付费转化的信任基础。可以直接复用现有 articles 表。

  • 入门教程：「命理是什么」「怎么读懂自己的命盘」「十神到底指什么」
  • 深度解读：格局、用神、大运流年 —— 这是真正的付费点
  • 案例库：脱敏真实案例，讲思考方式而非预测结果（合规关键：讲「怎么做决策」不讲「哪天真发财」）
  • 命理师专栏：入驻者自带内容，解决冷启动的内容量
  • 避坑科普：「怎么识别收智商税的」「为什么不能承诺准确率」—— 这类内容在公域平台反而最安全、最容易过审
Ⅲ 社区型留存与裂变 · 占 10%

⚠️ 现状是半 UGC：评论可提交，但「提问/发帖」只能在后台 CMS 创建。需要改造。

  • 用户提问 → 命理师/网友解答：把现有 kind='problem' 的问题页从「单向发布」改成「用户可提交」（当前库里 kind 全是 post，0 篇 problem，等于这个能力还没启用）
  • 解盘打卡 / 日签：每日一签，分享带二维码 —— 天然裂变物
  • 话题讨论：现成评论系统（含楼中楼/点赞/有用/举报/通知）已完整，复用即可
Ⅳ 合规型防御 · 占 5%，但决定生死

这类内容不带来流量，但没有它，前三条全部白做。

  • 全站免责声明模板（每篇内容 / 每份报告 / 每个会话窗口强制注入）
  • 未成年人保护声明 + 前置年龄确认
  • 隐私政策 / 用户协议 / 服务协议（含敏感个人信息单独同意）
  • 命理师行为规范 + 红线词清单（入驻必读并勾选确认）
  • 退款规则 / 争议处理流程
  • 内容审核 SOP（人工 + 关键词双轨）

5.4 收费侧的两个必修缺口

缺口一：退款与争议（P0）

现状代码只处理了「付款成功」，没有任何退款路径。

  • 订单状态机需扩 refunding / refunded / disputed
  • 规则要前置公示：报告出稿前可全退、出稿后不退；咨询开始前可改期、爽约扣比例
  • 争议必须留痕（谁、何时、什么原因），这是被投诉时的唯一自证材料
  • 超时未交付自动退款（避免用户投诉到监管）
缺口二：给命理师的分账结算（P1）

B2B2C 的命脉，现在是零。

  • payouts 表：结算单、可结算余额、提现申请、打款凭证
  • MVP 建议人工结算（命理师发起申请 → 后台审批 → 线下打款 → 回填凭证），把钱留在银行侧
  • 收入分账记录必须双向可查：命理师看自己的，财务看全部的
  • 个税代扣问题需财务介入确认，不是技术问题但会卡住上线

七、风险与红线

类型风险必须做的动作
法律 被认定「利用迷信骗取财物」 不承诺预测结果、不恐吓消费（「不做会怎样」）、不重复收割同一用户（「加钱才能化解」）。 所有文案以「提供视角/参考/启发」表述。这条线一旦越过，从行政处罚直接跳到刑事。
法律 面向未成年人服务 后端强制年龄校验（不是前端隐藏按钮），下单、提问、咨询入口全拦；发现冒用要能封号。
法律 敏感个人信息泄露 出生时间/地点/照片加密存储；上传文件改私有 + 签名 URL（当前 /uploads 是裸公开的）；提供导出/删除通路；最小必要采集。
法律 涉医疗 / 投资建议 不得出现「治病」「调理身体」「哪只股票」类内容，这类是明确的法律禁区，且平台一旦被举报必然处理。
平台 公域账号被批量封禁 公域只做科普、绝不在标题/正文出现「算命/占卜/改运」；不留联系方式（用短链或粉丝群承接）；多账号分散，不要把鸡蛋放一个篮子。
资金 支付商户号被清退 / 资金冻结 不把全部收入压在单一商户号；会员费优先（名义更好解释）；保留 manual 通路作为兜底；账务清晰可自证。
商业 供给端（命理师）质量不可控 入驻审核 + 红线词培训 + 评价体系 + 争议处理；平台的品牌风险来自入驻者的话术，不来自代码，所以内容风控是商业基础设施而不是合规装饰。
技术 命盘结果不可复现 引擎版本 + 流派配置随盘落库；同输入必须产出逐字节相同结果（快照测试）；参考 iztro 版本变更的教训。
