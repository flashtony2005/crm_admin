0一页结论

The One Thing

官网首页的按钮写着「查看报表样例」，点进去是一篇文章。站点承诺「20+ 份可运行样例」，读者一份也跑不了。样例台要补的不是功能，是承诺与交付之间的那一步。

进度更新 · 2026-10-20 15:00

引擎侧已完成 M1 主体：29 份样例（含新增「收入结构·占比与帕累托」「部门预算执行·差异与预警」「门店销售·组内排名与组内占比」3 份）、5 标签页详情、Univer 画布渲染、Excel/CSV/JSON 下载导出、Logo 与 favicon 替换、gallery ↔ 设计器双向跳转。
三份新样例的断言已独立验算全部通过（帕累托合计 1,536,000 / 首行 31.64% / 末行 100.00%；预算差异 5 项 / 合计 4,560,000；门店合计 1,205,000 / 组内首位 43.66% / ★×3）。
本功能的剩余工作：路由形态定夺 + 搬进官网 + 埋点 + 留资（2.5–3.5 天）。

地基齐全

/api/public/track 接受任意 type（埋点零成本）；public_forms 已有 forms/leads 三表（留资直接用）。不用新造轮子。

关键约束 · 决定 v1 形态

rpx-server 源码首行注释写着 "No calculation handlers"，且有回归护栏断言 POST /render、POST /export 故意不存在。它只读固定产物。
→ 因此 v1 是「浏览 + 导出」而非「访客现场改定义」。真执行需另开通道，那是 v2，且必须先解掉安全边界（见 §3 非目标、§11 风险 R1）。

功能一句话

在官网新增 /samples 路由页：访客浏览 29 份中国式复杂报表样例，点开即看真实渲染结果（可读 Univer 画布、模板定义、数据来源、逐格校验），可导出 Excel / CSV / HTML —— 零安装、零注册、零配置。

为什么现在做（对照 PROJECT_REVIEW_2026-10-19）

那份评审的核心结论「不要继续加功能」是转向前写的（当时站名是「可可鸭」，做的是创作者变现站）。站点已转型 AI 报表引擎，原结论不成立，但「先证明有人愿意付钱，再证明架构能扩张」的原则依然有效 —— 样例台正是把「引擎能力」变成「可被看见的价值」的最短路径。

1问题陈述

问题

官网的转化叙事停在阅读。技术选型者读完 4 篇深潜文，认知停在「这个引擎有点意思」，但无法确认「它真能处理我要的那类报表」。转化卡在最后一个疑虑上：「说得好听，做不出来怎么办？」而引擎其实已经能跑 29 份真实中国式复杂报表 —— 这个证据没有被摆到读者面前。

谁在经历，多频繁

角色场景频率当前卡点
报表系统选型者（技术负责人）评估是否用 Rust 引擎替换现有 JVM 方案选型期一次性，但决定金额最大无法验证「扩展格/不规则分组」在真实数据上长什么样
开发者 / Agent 集成方想先跑一份 JSON 定义看效果高频探索期需 clone 仓库、cargo build、准备 CSV —— 门槛过高
潜在客户决策人要向团队证明「值得上」汇报前一次要能贴一张真实报表截图进 PPT，没有
SEO / GEO 抓取方抓取站点理解产品能力持续只有 /llms.txt、/agent.json 给机器，人类可读的产品能力页缺失

不解决的代价

  • 需求侧成本：events 表 75 条事件全是 article_view，无 signup、无 order_paid —— 漏斗根本不存在，任何转化讨论都建立在 0 上。
  • 信任成本：对一个卖重写换正确性（行为对拍、逐格一致）卖点的产品，只给文章不给样例是自相矛盾的。卖点是「可验证」，交付却是「请相信我」。
  • 内容资产浪费：29 份样例 + 逐格 checks 断言躺在引擎仓库里，等于零营销价值。
  • 机会成本：每多一篇长文，边际说服力递减；同一份引擎能力，做成可交互样例的转化效率远高于再写一篇。

3非目标

非目标是这份规格里最省成本的部分。每一条都写明为什么砍，避免实现期范围蔓延。

不做的事为什么
访客现场编辑定义并实时执行 当前引擎无公开实时执行通道：rpx-server 无计算 handler，rpx-runtime 的执行入口是 Rust 库函数不是 HTTP 端点。新开通道 = 新安全面（访客输入 → 表达式求值 → SQL/文件读取），必须独立设计沙箱、限流与超时。这不是 v1 该背的，见 v2 讨论（§12 Q3）。
访客上传自己的数据源 同上，且涉及数据外泄与资源滥用；且与「展示引擎能力」这个目标无关。
在线代码编辑器 / IDE 式体验 引擎的 web/ 已是完整 designer（Univer + 属性面板），带 Bearer 鉴权、私有部署假设。官网再做一个编辑器是重复造轮子，且会让访客面对「两个产品」的困惑。
样例台内的账号体系、登录墙 与 G1 直接冲突。本功能的全部说服力来自「零门槛」——加登录就把最大的优势砍了。留资放在看完之后，不放在进入之前。
PDF 导出 技术约束：PDF 需本机 Chrome/Chromium/Edge，找不到浏览器就明确失败不静默降级（引擎 README 明示）。部署环境不保证有浏览器 → 官网导出 PDF 会出现「用户点了就报错」。v1 只做 Excel / CSV / HTML，PDF 标记为「引擎本地支持」。
把样例台做成登录后可见的会员权益 会员/积分/订阅是创作者变现站遗留模型，对 B2B 选型者是错配。样例是获客资产不是付费墙后的商品。
在样例台内做定价、套餐、支付 另开一个功能（定价与试用申请）。本 PRD 只在样例详情页放一个「联系/试用申请」入口，承接既有 public_forms 能力，不设计支付。
移动端完整适配 报表网格在窄屏天然横向溢出（引擎已有 fitColumns 逻辑说明这个问题真实存在）。v1 明确移动端只保证「可访问 + 可看定义/数据/校验」三个信息页签，结果画布提示建议横屏。把网格硬塞进手机屏是本末倒置 —— 报表是桌面场景。
范围控制条款

后续任何新增需求，必须同时移除一条 P1 或延期一个里程碑。若有人提议「顺便加个编辑器 / 加个上传 / 加个 PDF」，按本节拒绝。

8.2 接口契约

公开读接口（新增 2 条）

GET /api/public/samples
    → { ok, data: { version, run_id, total, sections: [...],
                    reports: [{ id, title, section, description, features,
                                status, run: { template_rows, template_cols,
                                               rows, cols, pages,
                                               inputs: [...], checks: [...] } }] } }

GET /api/public/samples/{id}
    → { ok, data: { ...单份样例 + base 相对路径 + export_urls: { xlsx, csv, html } } }
契约纪律（照抄项目血泪教训）

① 响应包统一 {ok, data, total, error}；前端取值恒用 j.data ?? j。
② 若手写入口 DTO，必须 #[serde(rename_all="camelCase")]（配 snake alias）—— 历史上 inviteCode 因缺它被静默丢弃，直接导致邀请奖励永不发放（资损）。
③ {id} 路径参数按分量白名单校验（^[a-zA-Z0-9-]+$），不靠 starts_with 判前缀 —— 目录穿越按分量判才有效。

静态产物路径

/t/coucouya/report-gallery/catalog.json
/t/coucouya/report-gallery/run-<nanos>/<id>/template.json
/t/coucouya/report-gallery/run-<nanos>/<id>/run.json
/t/coucouya/report-gallery/run-<nanos>/<id>/<datafile>.csv
/t/coucouya/report-gallery/run-<nanos>/<id>/<artifact>.{xlsx,csv,html}

注意：run_id 含时间戳，不要硬编码。清单接口返回的 base 字段即权威相对路径，前端据此拼装 —— 与引擎 gallery-data.ts 现有做法一致。

8.3 前端路由扩展

// router.ts 的 Route 联合类型新增两态
| { kind: 'samples' }                      // /samples
| { kind: 'sample'; id: string }           // /samples/{id}

// 解析顺序要求（照抄现有注释里的教训）：
//   精确匹配 '/samples' 必须放在前缀匹配 '/samples/(.+)' 之前，
//   否则清单页会被当成 id 为空的详情页（页面直接空掉）。
两个必须遵守的项目既有约束

① 深链依赖服务端 SPA 兜底：templates.rs::serve_file 读不到文件会回 index.html，但带已知资源扩展名的缺失文件一律 404（避免 HTML 冒充 JS 触发 MIME 报错）→ 样例 id 不能以资源扩展名结尾（现有 id 均安全）。
② 站内链接必须写根相对路径（如 /samples/xxx），由 router.ts::withBaseHref() 补 base —— 写绝对路径在生产（/t/coucouya）会 404，dev 却是正常的，这是个只在生产暴露的坑。

建议在动官网之前先做一次引擎侧提交：① 核心引擎改动与样例/品牌改动应当分成两个提交（前者是引擎能力，后者是品牌与样例内容）；② crates/rpx-ds/probe.db 是本地探针产物，不应入库，应加进 .gitignore。

理由：官网侧要消费的是已提交、可复现的产物。如果引擎改动只在工作区，官网搬运的产物就无法从 git 历史重建 —— 这直接违反 R2 风险缓解条款（产物与源码脱节）。

  • 目录内文件名含 .. 或路径分隔符时被拒
  • 越权访问其他租户数据不可能发生（单租户，但不得引入硬编码绕过）
