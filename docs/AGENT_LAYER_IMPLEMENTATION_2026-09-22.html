做法：服务期头注，而不是构建期静态快照

新建 server/src/agent_layer.rs。核心是一个纯函数 inject_head(html, &HeadInjection) -> String：templates.rs::serve_file 在伺服 模板入口 index.html（含深链兜底那一次）时，先从 DB 采一份 Facts 快照，生成 HeadInjection，做纯字符串合并后再返回。磁盘上的产物文件一个字节都没改。

为什么不用构建期快照服务期头注
后台改站点标题 / 改文章标题要重跑前端构建 + 部署脚本下一次请求即生效，零部署动作
需要在构建流水线里维护一份数据导出数据直接从 site_settings / sections / tiers / articles / nav_links 读，天然不会与后台配置漂移
动态路由 /post/<slug> 需要预渲染所有文章按请求解析 post/<key> / read/<key> / articles/<key>，按需注入该篇事实
四个刻意的设计决定（都有理由，不是随意）
  • 站点根的 <title> / description 保留模板原值，不强行用 DB 覆盖。那是发布者写给人看的门面文案。但 og:title / og:description 取页面自身的同一份文本 —— 两处各取一个来源会让同页出现两种说法，看起来像配置错乱，也是机器判断实体时的噪声。
  • 注入态不发 Last-Modified、不做 304。内容来自 DB 而非文件，文件 mtime 无法代表内容是否变化。沿用文件时间戳会让「后台改了标题但客户端收到 304」变成无法排查的陈旧内容。子资源仍保留 max-age=86400 + 条件请求。
  • 注入前先摘掉模板里同名 meta（og:type/url/title/description/site_name、canonical、已有的 ld+json），保证输出确定性、不出现同页重复声明。
  • 注入失败绝不影响页面。DB 不可用 / 解析异常 → 只打 stderr 日志、原样返回 HTML。头注是增强，不是可用性依赖。

顺带修好的、比 GEO 更基础的一件事

OG 为 0 意味着连人分享链接都没有预览卡。这条不是 GEO 问题，是所有人分享公众号/微信/X 链接时都会看到的空白卡片。现在站点根与每篇文章都有 og:title / og:description / og:url / og:type / og:site_name / og:locale，以及显式的 twitter:card / twitter:title / twitter:description / twitter:url（X 对 og:* 的回落并不可靠，且 card 必须按实际有无封面给值 —— 声明 summary_large_image 却无图，抓取器会渲染成无图大卡，比 summary 更糟）。

三个容易被做歪的点，本次的处理
  • capabilities 只声明今天真实存在的端点。声明一个不存在的接口会让 Agent 调用失败并把整站判为不可信，比不声明更糟。所以清单里是 read_home / list_articles / read_article / list_tags / list_plans / read_feed —— 全是已实测 200 的只读接口。写入、发布、支付类接口明确写进 limits：「不对外部 Agent 开放，需站内权限与人工审批」（这与项目里已有的审批链路一致）。
  • topics 取文章标签，不取区块标题。第一版把区块标题一起并进去，结果产出「组织、实验、Web3」——「组织」「实验」是站点结构名，会让 Agent 误判「这个站点讲组织管理」。改为：优先文章标签，完全没有标签时才退回区块标题。实测结果 ['支付方式','外币卡','手机卡','港卡','U 卡']。
  • robots 的 AI 组与 * 组规则相同，是刻意的。功能上等价，价值在于声明意图：日后若收紧 * 组，被判为「欢迎」的爬虫不会被动连带失联。名单会随厂商更名/新增而变化，所以真正的兜底仍是 * 组 —— 漏掉一个新爬虫也不影响可达性。

/robots.txt 另外把 /api/ 保持在 Disallow 内：机器读内容走 HTML（已有头注）与 /llms.txt / /agent.json，不必让爬虫把 API 当抓取入口压。

3段 2：付费内容的机器暴露边界（含端到端验证）

这一条不是「加个过滤」，而是先定策略，再在三个通道上分别落实。策略：付费内容的标题与摘要可公开引用（那是转化入口），正文一律不给。

通道处置理由
/sitemap.xml收录 付费项（只出 URL）只暴露 URL。让付费内容保持可发现、可被索引，付费墙由页面层与 API 的 402 守住。排除它等于让这些内容对搜索与 Agent 完全隐形，主动放弃转化入口。
/rss.xml排除 付费项RSS 是免费分发通道，<description> 是可自由转发的摘要，而订阅器天然无法完成付费。把付费项写进去，等于对外发一份永远拿不到全文的承诺。
/llms.txt · /agent.json标注（标题+摘要+「会员专享」/ access:subscription）让 Agent 知道「有这篇、要付费」，而不是「内容为空」——后者会让 AI 在回答「有没有讲 X 的文章」时给出错误结论。
/t/<slug>/post/<key>头注但不给正文JSON-LD 标 "isAccessibleForFree": false，不写 articleBody；noscript 只给标题 + 摘要 + 门槛说明。正文提取在这一层就短路，不给任何「提取失败时误落正文」的机会。

4执行中发现并修掉的两个现网缺陷

SEO 死链sitemap 发布的 7 条 URL 里 6 条是 404

现象（改前实测）：sitemap 的 <loc> 全是 http://localhost:8088/read/<key> 与根路径 http://localhost:8088/，逐条请求 6/7 返回 404。等于长期向搜索引擎提交一份死链清单。

双层根因：

  • seo.rs::home_loc / article_url 未配置 PUBLIC_HOME_URL 时回落 {base} 与 {base}/read/{key}。但后端根路径是后台 SPA（spa_fallback 伺服 dist-app），不是对外门面 —— 把 SEO 门面指向后台上就埋下了这条死链。
  • main.rs::static_dir 默认 ./dist-app（相对 cwd）。服务器 cwd 是 server/，而产物在仓库根的 dist-app/ —— 不设 STATIC_DIR 时后台 SPA 整体 404，把「回落路径本身就是错的」和「后台没起来」两个问题叠在一起。
已修：新增 seo::home_base() —— PUBLIC_HOME_URL 优先，未配置时自动解析当前激活模板取规范主页 /t/<slug>；文章链接统一为 {home}/post/{key}（与主页前端路由约定一致）。实测 7/7 → 200。同一修正也应用到 RSS 的 channel/ item 链接与 agent_layer。
待你处理（未改）：static_dir() 的默认值问题仍在 —— 生产部署若依赖后台内置页面，需要显式设 STATIC_DIR，或像 templates::templates_dir() 那样逐级向上找目录。本次未动它，因为改静态目录解析会影响后台可用性判断，属于另一条链路。
可用性主页地址带尾斜杠时 404

axum/matchit 把 /t/<slug> 与 /t/<slug>/ 当成两条不同路径，只注册了前者，于是 /t/coucouya/ 落到兜底并 404。「主页地址会不会带尾斜杠」由用户输入决定，不该靠碰运气 —— 何况 sitemap 与 RSS 发布的地址也不应是死链。

已修：spa_fallback 增加窄条件归一化 —— 只处理「恰好一个非空段的 /t/xxx/」，其余一律照旧走 SPA 逻辑（不做通用尾斜杠剥离，避免影响后台路由）。302 而非 301：模板可切换，别让浏览器永久记住。实测 /t/coucouya/ → 302 → /t/coucouya；/t/coucouya/post/ 不被误伤（仍走深链兜底）。
