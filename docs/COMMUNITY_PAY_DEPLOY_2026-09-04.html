②功能地图（P0–P3）

P0 · 邀请注册 + 内容付费墙

  • 邀请码门控：site_settings.member_invite_required 开关，注册原子核销（额度/有效期/启停）
  • 文章付费分级 paid_level：0 公开 / 1 订阅 / 2 积分买断 / 3 仅邀请，优先级高于旧 visibility
  • HTTP 402 墙：返回 {locked, reason, paidLevel, pricePoints, preview}，前台按类型渲染解锁按钮

P1 · 积分 + 订单 + 邀请奖励

  • 积分流水 points_ledger 是唯一事实源（余额 = SUM(delta)，带 balance_after 快照）
  • 每日签到 / 兑码（积分或会员天数）/ 积分买断单篇（幂等）
  • 订单（充值/订阅）人工确认收款：原子 pending→paid，自动发货
  • 邀请奖励延迟到账：好友首次付费后补发（每好友一次，防薅）

P2 · 微信 Native 在线支付

  • API v3 标准接入：SHA256withRSA 请求签名 → Native 下单 → code_url → 二维码 SVG
  • 回调验签（平台公钥可选强制）+ AES-256-GCM 解密 + 幂等发货（与人工确认同链路 fulfill_order）
  • 对账：按日×渠道×状态透视 + 一键关闭 24h 超时订单
  • 商户凭据存 site_settings，后台可视化管理（脱敏显示）

P3 · 会员中心 + 看板 + 到期提醒

  • /t/member 会员中心模板页：概览/钱包/订阅/订单，主题自动跟随 active 模板（neon 暗色 / editorial 纸感 / 默认浅色）
  • 看板「社区经营」：收入/订单/付费会员 KPI + 14 天收入与新增会员趋势 + 临期会员表
  • 到期提醒：planDaysLeft / planExpiring(≤7天) / planExpired，会员页与会员中心横幅提示

③部署步骤

3.1 编译与启动（Windows 本机）

cd F:\project\admin\server
build_sections.cmd        :: 双击或命令行运行；自动清理构建锁 → 编译 → 重启 :8088
  • 脚本使用温暖目标目录 tgt_build4 增量编译（约 2–5 分钟）；本次含新增依赖（rsa / aes-gcm / qrcode / base64），首次编译会额外下载并编译新 crate
  • 数据库迁移在启动时自动执行（版本化 MIGRATIONS，0004/0005 已含 P0/P1 表，P2/P3 无新增迁移）

④微信支付联调指南

4.1 商户参数获取（微信商户平台 pay.weixin.qq.com）

  1. 开通产品：产品中心 → 开通「Native 支付」
  2. APIv3 密钥：账户中心 → API 安全 → 设置 APIv3 密钥（32 字节字符串，自己设定并妥善保管）
  3. 申请 API 证书：同页申请商户 API 证书，下载证书工具导出：商户私钥 apiclient_key.pem（完整 PEM 内容）与证书序列号
  4. 平台公钥/证书：API 安全 → 微信支付公钥（2024 年后新商户默认公钥模式），复制微信支付公钥 PEM（用于回调验签；旧商户为平台证书模式，需下载平台证书并配置其公钥）
  5. 绑定 AppID：账户中心 → AppID 账号管理（公众号/小程序/开放平台任一）
  6. 回调域名：无需单独配置，但 PUBLIC_BASE_URL 必须为公网 HTTPS/HTTP 可达地址且 ICP 备案（微信要求）

4.2 后台配置

管理后台 → 订单 → 展开「微信支付配置（Native 扫码）」，填写：

字段对应参数说明
AppIDappid已绑定的公众号/小程序 AppID
商户号 mchidmchid纯数字商户号
证书序列号serial_no商户 API 证书序列号（40 位十六进制）
APIv3 密钥api_v3_key第 2 步设置的 32 字节密钥（回调解密核心）
商户私钥 PEMprivate_keyapiclient_key.pem 全文（含 BEGIN/END 行）
平台公钥 PEMplatform_pub_key微信支付公钥全文（选填；配置后回调强制验签）
⚠️ 密钥项保存后仅显示尾 4 位掩码；留空提交不会覆盖已保存的值。全部参数就绪后配置卡角标变为「已就绪」，会员端才会显示微信扫码入口（未就绪时下单会提示缺失项）。

4.3 本地/无公网环境怎么验证

  • 回调不可达时，扫码支付成功但订单不会自动到账——可用商户平台「交易账单」核对后，在后台订单页人工点「确认收款」兜底（幂等，不会重复发货）
  • 或者用内网穿透（frp / ngrok）把 8088 映射到公网，并将 PUBLIC_BASE_URL 指向穿透地址做全链路联调
  • 订单状态接口 GET /api/public/orders/{orderNo} 可随时查询，前端轮询即基于它

⑤支付链路与回调验签

图 2 · 双轨支付链路：在线扫码自动到账为主，人工确认兜底，二者幂等互斥

回调验签说明

  • 签名验证：微信回调头 Wechatpay-Timestamp / Nonce / Signature，验签原文为 {ts}\n{nonce}\n{body}\n，用平台公钥做 SHA256withRSA 校验。配置了平台公钥则强制验签，不通过直接拒绝
  • 密文解密：回调体 resource.ciphertext 用 APIv3 密钥做 AES-256-GCM 解密（nonce 12 字节，associated_data 参与运算）。攻击者没有 APIv3 密钥就无法构造出能解密成功的密文——即使跳过验签，回调依然具备防伪造能力
  • 应答约定：处理成功返回 {"code":"SUCCESS"}（HTTP 200）；失败返回 500 + {"code":"FAIL"}，微信会按退避策略重试，因此发货必须幂等（本实现通过数据库原子状态转换保证）
  • 金额校验：回调含 amount.total，与订单 amount_cents 同源生成；如需更严格可加一道比对（后续项）

⑦功能验证清单

站长（后台 5188 → 8088 API）

  • 会员页：开启邀请码门控 → 创建邀请码（额度/有效期）
  • 文章页：设置 paid_level=2 + 积分价格 → 预览 402 墙
  • 订单页：填写微信支付配置 → 角标变「已就绪」
  • 订单页：人工订单「确认收款」→ 发货 + 邀请奖励提示
  • 订单页：对账卡切换 7/30/90 天；「关闭超时订单」
  • 统计看板：社区经营 KPI、收入/新增会员趋势、临期会员表
  • 模板页：切换 neon/editorial → 模板列表「会员中心」预览正常

会员（公开站）

  • 邀请注册：开邀请制后无码注册被拒、有码成功
  • /t/member：登录 → 签到 +积分 → 兑码 → 流水更新
  • 充值：微信扫码弹二维码（已配置时）→ 支付后自动到账；或人工转账 → 后台确认到账
  • 订阅：套餐「微信扫码订阅」→ 到账后计划状态与有效期更新
  • 积分买断：/read/{slug} 积分墙 →「用 N 积分解锁」→ 刷新后可读且不重复扣分
  • 到期提醒：临期（≤7 天）黄横幅、过期红横幅正确显示
  • 主题自适应：切换模板后 /t/member 配色跟随变化

⑧上线检查清单

  • 编译部署：build_sections.cmd 编译通过、8088 重启成功、GET /api/public/site 正常
  • 数据库：迁移日志无报错；orders / points_ledger / invite_codes / redeem_codes 表存在
  • 公网地址：PUBLIC_BASE_URL 已设为公网可达域名（HTTPS 建议），回调路径可达
  • 微信支付：后台配置齐全（角标「已就绪」）；商户平台已开通 Native 产品、绑定 AppID
  • 小额实付验证：用真实微信扫一笔最低金额订单，确认回调自动到账 + 对账卡渠道显示「微信扫码」
  • 凭据安全：APIv3 密钥/私钥仅存于服务器 site_settings；不要提交到 git / 分享截图
  • 兜底通道：收款码图片与人工确认流程已就绪（在线通道故障时可切换）
  • 站点内容：付费文章 paid_level/价格设置复核；邀请码额度与积分规则（points_signin / points_invite_reward）复核
  • 备份：cms_live.db 定期备份（含 site_settings 中的支付配置）

⑨已知限制与后续规划

  • 回调金额强校验：可在 notify 中比对 amount.total 与订单金额（当前同源生成，风险低）
  • 平台证书模式：旧微信商户为平台证书（非公钥）模式，需下载证书并自动轮换——当前支持手工粘贴其公钥
  • Stripe 正式通道：orders.channel 已预留 stripe，可将 Stripe webhook 映射到 fulfill_order 统一发货
  • 到期提醒通知化：当前为页面横幅 + 看板列表；可接 webhooks_out / 邮件（notify.rs）做主动推送
  • 价目表化：积分充值 1 分/积分的定价写死在代码（P1 简化），可升级为可配置价目
