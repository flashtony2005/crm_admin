rpx run 与五种导出：从模板到交付物

从模板到交付物

rpx run 是整条链路里唯一「真算」的一步：读模板、取数据、求值、分页、写产物。前面所有命令（lint、template validate）都是在为它做准备。

最小的一次执行：

rpx run payroll.json --out-dir out --data-dir examples/r-model --export xlsx

本文讲三件事：五种导出分别是什么、返回的 JSON 该看哪些字段、以及两个实测才会遇到的坑。前置的两步是环境自检与静态检查。

五种导出格式

--export 接受 5 种，而且可以重复传（它是追加语义，不是一次传多个值）：

--export csv --export xlsx --export print-xlsx --export html --export pdf
写成 --export csv xlsx 会直接报参数错误——第一个值之后的会被当成多余的位置参数。
格式产物用途
csvreport.csv给程序消费；不带样式
xlsxreport.xlsx给人在 Excel 里再用
print-xlsxreport-print.xlsx带打印设置（分页、纸张）的 Excel
htmlreport.html网页预览；走打印渲染管线
pdfreport.pdf需要本机有 Chrome/Chromium/Edge

html 和 pdf 共用同一条渲染管线（先渲染成页面，pdf 再交给浏览器打印），所以两者的版式是一致的——你在 html 里看到的，就是 pdf 会出的样。

返回的 JSON 该看哪些字段

我拿工资表实测了一次五种全导，返回大致这样（节选）：

{
  "ok": true,
  "data": {
    "layout": { "cols": 7, "rows": 11, "page_count": 1,
                "paginated": true, "x_pages": 1, "y_pages": 1,
                "paper_w_pt": 487.56, "paper_h_pt": 700.16,
                "row_num_per_page": 20 },
    "result":  "out/artifacts/result.json",
    "run": {
      "artifacts": { "report.csv": ..., "report.xlsx": ...,
                     "report-print.xlsx": ..., "report.html": ...,
                     "result.json": ..., "workbook.json": ... },
      "diagnostics": [ ... ],
      "engine_version": "0.16.0",
      "inputs": [ { "kind": "file", "dataset": "pay",
                    "path": ".../payroll.csv", "sha256": "2522d3..." } ]
    }
  }
}

layout：先看分页，不是先看数据

page_count / x_pages / y_pages 是第一时间该看的字段。如果 x_pages 大于 1，说明表格横向溢出了纸张——纸面上通常不可接受。纵向多页是正常的分页，横向多页基本都是要修的。

paper_w_pt / paper_h_pt 给的是纸张尺寸（点），row_num_per_page 是每页行数。这几个数字一起决定了你的表能不能打印成一页。

inputs：数据溯源

每个输入数据集都记录了 path 和 sha256。这看着不起眼，但排查时极其有用：同一份模板、同样的命令，两次结果不一样，先比对 sha256——数据换了，结果当然会变。

diagnostics：比 ok 更重要

这是最需要注意的一点：ok: true 不代表一切顺利。

实测一次请求了五种导出、其中 pdf 失败（本机没有浏览器），返回是这样的：

"ok": true,
"diagnostics": [
  { "code": "EXPORT_FAILED", "format": "pdf", "severity": "warning",
    "stage": "export",
    "message": "未找到 Chrome/Chromium/Edge，无法导出 PDF；可设环境变量 RPX_CHROME=<浏览器可执行文件路径>" }
]

pdf 没生成，但整次 run 仍然算成功，csv / xlsx / print-xlsx / html 全部正常产出。这是有意的降级设计：单个导出失败不该拖垮整次运行，失败以 warning 形式挂在诊断里，带 format 字段指明是哪一种。

所以正确的判读顺序是：先看 ok，再看 diagnostics，最后按 artifacts 里实际有哪些文件来确认你要的格式在不在。

两个实测才遇得到的坑

坑一：--out-dir 必须是不存在的目录

第一次跑我顺手先建好了输出目录，结果：

IO_ERROR | 当文件已存在时，无法创建该文件。 (os error 183)

把目录删掉、让 CLI 自己建，就正常了。也就是说 --out-dir 的语义是「创建这个新目录」而不是「输出到这个目录」。

重复跑同一个目录也会撞上同一个错。自动化脚本里记得每次用新目录，或者跑之前先清掉：

rm -rf out && rpx run tpl.json --out-dir out --export xlsx

坑二：pdf 依赖本机浏览器，且失败是静默的

前面已经说了失败会降级成 warning。这里补一句怎么让它成功：设 RPX_CHROME 环境变量指向浏览器可执行文件。

RPX_CHROME="C:/Program Files/Google/Chrome/Application/chrome.exe" \
  rpx run tpl.json --out-dir out --export pdf

不确定本机有没有、能不能用，先跑 rpx doctor，它会明确告诉你 pdf.available 是 true 还是 false。这篇讲了 doctor 的自检逻辑。

跑完之后：result.json 才是证据

产物目录里有两个值得单独说的文件：

  • result.json：逐格结果。每一格都带 address（如 A1）、origin（来自模板哪一格）、origin_coordinates、以及 value。它是断言对拍的对象——「这一格应该等于什么」就是在跟它比。
  • workbook.json：带样式的完整工作簿快照，html / pdf 就是从它渲染的。

想改定义再来一遍，走模板补丁；想不打开 Excel 就核对结果，用：

rpx result inspect out/artifacts/result.json --limit 5

它支持 --range（按区域）、--origin（按模板原格筛）、--limit / --offset（分页，每页上限 500）。实测返回的每格长这样：

{ "address": "A1", "row": 1, "col": 1,
  "origin": "A1", "origin_coordinates": [1, 1],
  "left_head_origin": "0", "top_head_origin": "0",
  "value": { "type": "string", "value": "员 工 工 资 表" } }

origin 与 address 的区分是关键：扩展之后，结果里的第 3 行可能来自模板的同一格。断言要锚在 origin（模板原格）上才不会被数据行数变化带偏——这一点在样例的断言机制里是核心。

常见问题

能不写盘、直接输出到 stdout 吗？

run 必须给 --out-dir，产物是文件。但它的摘要会打到 stdout（JSON），你可以从中读 layout 和 diagnostics；要看具体格值，再对 result.json 用 result inspect。

参数怎么传？

模板里声明的参数用 --params-file 给，- 表示从 stdin 读——方便管道里串。注意 源码与结果必须用文件路径，只有 --params-file 和 --patch-file 支持 stdin。

一次能导多少数据？

Excel 有硬边界：16384 列 / 1048576 行。SQL 数据集默认最多取 100000 行，可用 RPX_SQL_MAX_ROWS 覆盖。这些值都能从 rpx capabilities 当场读到，不必记。

导出成功了但内容不全，会提示吗？

会。有专门的 EXPORT_PARTIAL 诊断码，用于「导出成功但内容不全」的情况（当前只用于 html / pdf 跳过图表），诊断里会列出被跳过的图表名。同样是 warning，不影响 ok。
