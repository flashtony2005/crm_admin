二、🔴 上线前必办（半天可完成）

#事项为什么阻断办 法
1种子账号还是 demo1234
db.rs:824		 owner/editor/viewer 三个后台账号密码是公开仓库里写死的 demo1234，且 must_change_password 默认 0——没有任何机制强制改密。上线等于把后台钥匙贴在门上。 上线前登录改密（改密后 token_version+1 全端失效），或直接在库中 UPDATE。
2全库零备份 「完全自持」意味着没有数据库厂商兜底：SQLite 单文件，磁盘坏 / 误操作 = 全站数据（会员、订单、流水）一次清零。这是自持系统最典型的翻车点。 最简：Windows 计划任务跑 sqlite3 cms.db ".backup backup-YYYYMMDD.db" + 拷贝到另一块盘/网盘；进阶：Litestream 实时复制。备份要做恢复演练一次。
3会员登录无限速
members.rs		 login_locks（5 次锁 15 分钟）只挂在管理员登录上；会员登录接口对公网开放、可无限暴力破解。 把 auth.rs 的 login_locks 查锁/计数复用到 members_login，半小时工作量。

main.rs:201		 交互式 GraphQL 控制台匿名可访问，等于把数据模型地图贴出来。 CMS_ENV=production 时直接不挂该路由（一行判断）。
7公开评论/表单无防滥用 无 captcha/honeypot/限速，可脚本刷评论、刷表单线索，污染审计与看板。 最轻：honeypot 字段 + 同 IP 每分钟计数（复用 SQLite 表）。
8无退款链路 误付/客诉只能去微信商户后台手工退，系统侧无记录 → 对账漂移。 短期：商户后台退款后，后台订单补「已退款」状态 + 对账口径排除；中期接 v3 refund API。

四、🟡 P2：择期（不阻断）

  • 可观测性：无 tracing/结构化日志、无优雅停机（SIGTERM 直接掉，在途请求与 webhook 投递靠 outbox 兜底——有兜底，但排障只能靠 stderr 与审计表）。
  • 会员 token 不可撤销：MemberAuth 仅验签不查库（members.rs:24 提取器），封禁会员后其 token 仍可用最长 30 天；管理员侧已有 token_version 机制，会员侧未接入。
  • 邮箱未验证：注册可填任意邮箱（含他人邮箱），影响通知触达与找回密码的可信度。
  • 部署面：需自备 TLS 反代（Caddy 最省事，自动 HTTPS）、进程守护（NSSM/计划任务）、CMS_ENV=production + JWT_SECRET + CORS_ORIGINS + PUBLIC_BASE_URL 四件环境变量。
