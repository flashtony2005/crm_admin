从 8 行数据到一张排名表：我让 AI 写「门店销售 · 组内排名与组内占比」的全过程

月初经营会前一天，区域经理发来一张手绘的草图：每个大区内部，门店销售排第几、占大区多少、谁是组内第一；最下面一行合计，回到全公司口径。这张表用 Excel 拖公式要半小时，还容易把排名写成全员混排。我把它交给 AI，拿回一份 JSON 模板，一条命令跑通，四项断言全部通过。这篇是从零到跑通的完整过程——照着做，十分钟可以复现画廊里这张真实报表。

一句话答案：组内排名是「同组比我大的个数加一」，组内占比是「本店销售额除以同组合计」。根坐标 `0 负责取出整个明细集合，条件 A4==$A4 负责收窄到同一大区，合计行不写条件、回到全体。样例数据 8 行、模板 1 份、命令 1 条，四项独立预期全部通过。

一、需求从哪里来：区域经理的那张表

区域经理的原话是：「别给我全员排名，我要看每个大区内部谁打谁。」这句话拆开是三个口径要求，每一个都落在模板的一处写法上。

他的要求口径模板里怎么落
组内排名只跟同大区的门店比同大区比我大的个数，加一
组内占比分母是本大区销售额本店销售额除以同大区合计
合计行回到全公司 8 家不过滤条件，对整个明细集合求和
大区列合并三家门店只写一次「华南」扩展列加 merge_same 同值合并

这三个口径是全文的纲。排名、占比、合计分别对应三种集合范围：同组、同组、全体。写错任何一处，表照样能跑出来，但数字是错的——所以第七章的核对一步都不能省。

二、数据准备：三列八行，一分钟的事

数据只有一张宽表，三列：region 是分组键，store 是明细键，amount 是度量。8 行，3 个大区——华南 3 家、华东 3 家、华北 2 家。全文就这一个文件：

region,store,amount
华南,深圳福田,186000
华南,广州天河,142000
华南,东莞南城,98000
华东,上海静安,205000
华东,杭州西湖,167000
华东,南京鼓楼,121000
华北,北京朝阳,198000
华北,天津和平,88000

保存为 store-sales.csv，UTF-8、逗号分隔。模板里要显式声明分隔符：

{"name": "sales", "file": {"file_name": "store-sales.csv", "encoding": "UTF-8", "delimiter": ","}}

这句 delimiter 是我实测过的最贵的一个字段。删掉它之后，同一份模板在三道关卡得到三种答案：

关卡命令实测结果
静态校验template validateok exit 0——放过，它不读数据
数据探针template validate --probe-dataok exit 4，错误码 DATA_SHAPE，指针指到 /datasets/0/file/delimiter
真跑runok exit 5，CALCULATION_FAILED，hint 提示「文件没被切分」

探针的原话是：「数据集 sales 只解析出 1 列『region,store,amount』，文件没有被切分」。exit 5 的 hint 还顺手给出修法：给该数据集的 file 加 "delimiter": ","。这就是这套 CLI 的设计哲学——错误码、指针、hint 三件套一次给全，不用猜。

三、把需求讲给 AI 听：四句硬约束

我没有说「帮我做个门店排名表」。需求说得越随意，交回来的东西越需要返工。我给了四句约束，外加一道交付闸门。

约束为什么
一列驱动扩展，其余列 left_head 跟随多列都写 vertical 会让扩展相乘；仓库实测记录里，6 行明细炸成 798 行
组内口径用根坐标取集合、用条件收窄不写死任何格号，数据从 8 行变 80 行公式不用改
合计行回到全体合计与明细是两种口径，写在两种集合上
不写 border当前导出链路不落地边框，写了也是静默无效；视觉层次靠表头与合计行底色

外加一道闸门：valid: true 不算数，必须真跑并断言产物。静态校验的 checked 只有 6 项，data_loading、calculation、pagination、export 四项明写在 deferred 里——它证明不了值算对。这道闸门的完整逻辑见《lint：拦截「不报错但产物错」的四类写法》。

四、AI 交回来的模板：逐格拆

交回来的是一份 6 行 × 7 列的 JSON 模板。数据源、列宽、行高之后，是 8 个格子——整张报表的逻辑全在这 8 行里：

{
 "version": 1,
 "grid": {"rows": 6, "cols": 7},
 "datasets": [{"name": "sales", "file": {"file_name": "store-sales.csv", "encoding": "UTF-8", "delimiter": ","}}],
 "cells": [
  {"row": 3, "col": 1, "text": "大区"},
  {"row": 3, "col": 2, "text": "门店"},
  {"row": 3, "col": 3, "text": "销售额"},
  {"row": 3, "col": 4, "text": "组内排名"},
  {"row": 3, "col": 5, "text": "组内占比"},
  {"row": 3, "col": 6, "text": "组内第一"},
  {"row": 4, "col": 1, "expr": "sales.group(region)", "extend_mode": "vertical", "merge_same": "vertical"},
  {"row": 4, "col": 2, "expr": "sales.select(store)", "left_head": "A4", "extend_mode": "vertical"},
  {"row": 4, "col": 3, "expr": "sales.select(amount)", "left_head": "B4", "extend_mode": "none", "format": "#,##0"},
  {"row": 4, "col": 4, "expr": "count(C4[`0]{C4>$C4 and A4==$A4})+1", "left_head": "B4", "format": "0"},
  {"row": 4, "col": 5, "expr": "C4/sum(C4[`0]{A4==$A4})", "left_head": "B4", "format": "0.00%"},
  {"row": 4, "col": 6, "expr": "if(D4==1,'★ 组内第一','')", "left_head": "B4"},
  {"row": 5, "col": 3, "expr": "sum(C4[`0]{})", "format": "#,##0"},
  {"row": 5, "col": 5, "expr": "sum(C4[`0]{})/C5", "format": "0.00%"}
 ]
}

（完整文件还带标题、表头底色、脚注等展示属性，随引擎仓库发布在画廊，路径 examples/r-model/store-ranking.json。）

逐格拆开看：

格表达式作用
A4sales.group(region)大区驱动列，纵向扩展；merge_same 把同值大区合并成一格
B4sales.select(store)门店明细列，left_head 指向 A4，跟着大区走
C4sales.select(amount)销售额，left_head 指向 B4，跟着门店走
D4count(C4[`0]{C4>$C4 and A4==$A4})+1组内排名：同大区比我大的个数，加一
E4C4/sum(C4[`0]{A4==$A4})组内占比：本店销售额除以同大区合计
F4if(D4==1,'★ 组内第一','')组内第一标注，排名为 1 才亮
C5sum(C4[`0]{})合计：不写条件，回到全体 8 家
E5sum(C4[`0]{})/C5占比合计，分子分母同集合，恒等于 100%

注意三条结构纪律：只有 A4 一个驱动列写 vertical，B4 虽然也从数据集取值，却写 none 加 left_head——多一个 vertical 就多一份扩展；C4 之后的计算列全部 left_head 指向 B4；明细行第 4 行与合计行第 5 行紧贴，不留空行。主格与从格怎么串，见《扩展格：中国式报表的核心算法》。

五、三个语法点：根坐标、$、{}

这张表的全部秘密在三个语法里。每一个我都做了对照实验——改一个符号，看集合范围怎么变。

根坐标 `0`：取出整个集合，不是收窄

C4[`0] 的意思是取 C4 的整个扩展集合——本例是全部 8 个明细实例，而不是当前行那一格。不写坐标的 C4 只是当前门店的销售额，没法跟别的行比。

模板脚注写的是「组内排名用根坐标定位到同一大区再统计」。我实测改了 D4 一行：只去掉 and A4==$A4、保留根坐标，排名从组内变成全员——8 家店的排名依次是 3、5、7、1、4、6、2、8（205000 的上海静安第 1，88000 的天津和平垫底）。

所以准确的说法是：根坐标负责取全量，条件负责收窄。两种说法都能跑出正确结果，但你改公式前必须知道是谁在收窄——删错一半，排名就悄悄换了口径。

$A4：绑定当前行的主格值

$ 绑的是当前格的主格。$C4 是当前门店的销售额，$A4 是当前行的大区。排名公式 C4>$C4 and A4==$A4 读作：在 8 个实例里，挑出销售额比我大、且大区跟我相同的那些。count 数个数，加一就是我的名次。

{}：不写坐标时，范围是共同主格

{} 里不写坐标时，管辖范围取「当前格与目标格的共同主格」。我在明细行里实测过：把 D4 改成 count(C4{C4>$C4})+1（去掉 [`0]），8 家门店全部变成第 1 名——因为明细行里 C4 与当前格的共同主格是门店自己，集合只剩一格，谁都比我大的个数是 0。

而合计行 C5 与明细行没有共同主格，所以 sum(C4[`0]{}) 顺顺当当回到全体，得到 1205000。同一对花括号，写在明细行是「自己」，写在合计行是「全体」——位置决定语义。

写法管辖范围实测证据
C4[`0]{A4==$A4}整个集合按条件收窄到同大区组内排名 1,2,3 / 1,2,3 / 1,2
C4[`0]{C4>$C4}整个集合，不收窄去掉条件后全员排名 3,5,7,1,4,6,2,8
C4{}共同主格：明细行里是门店自己去掉坐标后 8 家全是第 1 名
C4[`0]{}（合计行）共同主格为空，回到全体sum = 1205000

六、跑起来：一条命令与四个产物

模板存成 store-ranking.json，与 CSV 放同一目录，然后：

rpx template validate store-ranking.json
rpx lint store-ranking.json
rpx run store-ranking.json --out-dir ./out --export csv

三条全部 exit 0。run 的返回里带着版面摘要：模板 6×7 扩展成 13 行 × 6 列，1 页（page_count 1，x_pages 1，y_pages 1）。产物四个，各司其职：

out/
  run.json               # 运行记录：修订、输入指纹、耗时、诊断
  source/template.json   # 当时执行的源码快照
  inputs/params.json     # 实际参数（本表无参数，为 {}）
  artifacts/
    result.json          # 类型化结果，供 result inspect 查询
    workbook.json        # 展示快照，供网页与打印预览
    report.csv           # 显式 --export csv 才生成

lint 的结果值得单独说。它跑 8 项静态检查，这份模板命中 1 条 warning：L008，第 5 列宽 13mm，两个格用 0.00%，提示「两位以上小数在窄列会显示 ####；改 #,##0，或把列宽提到 18mm 以上」。加 --strict 就是 exit 3，闸门不过。我诚实地说一句：画廊里的定稿模板也带着这条 warning，默认闸门放行是因为占比列确实需要两位小数，13mm 也够显示「43.66%」。要不要为它加严，是你的工程决策，不是模板的 bug。相关阅读：capabilities 与 doctor 的自描述设计、run 与五种导出。

并列名次：实测行为

我把广州天河改成 186000，跟深圳福田并列，重跑：两家并列第 1，东莞南城是第 3 而不是第 2；占比变成 39.57%、39.57%、20.85%（分母变成 470000），合计仍是 100.00%。count 数「比我大的个数」，并列时天然拿到同样名次——这是竞赛排名，不是并列后占两个坑。

八、定稿前踩过的三个坑

这份模板定稿前返工过三次，三次都栽在同一个地方：扩展块里的集合语义。三个坑都有实测记录，抄模板前先看一遍。

坑现象规则
多列都写 vertical扩展相乘，6 行明细炸成 798 行只有一列驱动，其余列 none 加 left_head
扩展块里写 C4+D4引擎显式报 UnsupportedExpr——那是整列集合相加，不是两格相加计算列写数据集表达式，不做格间四则
明细行与合计行之间留空模板行空行被算进扩展块，合计被推到更下方两行紧贴，不留空行

还有一条展示层的：border 在当前导出链路不落地，模板里声明了也不会出现在 xlsx 与快照里。这份模板因此不写边框，层次全靠表头深色底与合计行浅色底——丑一点，但每一根线都是真的。

九、复现：十分钟从零做一张

完整复现流程，七步：

  1. 建目录，把第二章的 CSV 存为 store-sales.csv；
  2. 把第四章的 JSON 存为 store-ranking.json，与 CSV 同目录；
  3. rpx template validate store-ranking.json——exit 0，checked 6 项；
  4. rpx lint store-ranking.json——exit 0，1 条 L008 warning（可接受）；
  5. rpx run store-ranking.json --out-dir ./out --export csv——exit 0，13 行 × 6 列 1 页；
  6. rpx result inspect out/artifacts/result.json --origin C5——核对 1205000；
  7. 改一个数重跑，看排名与占比怎么动——比如把广州天河改成 186000。

想改口径，第五章那三种写法就是全部开关：收窄到组内、回到全体、排全员名次，各改一处。

常见问题

并列名次怎么算？count 数「比我大的个数」，并列同样名次；实测两家并列第 1 后，下一名是第 3。

想改成全员排名？删掉 and A4==$A4，保留根坐标，实测排名变为 3,5,7,1,4,6,2,8。注意只删坐标（变成 C4{}）会全部变成第 1 名——共同主格把集合收窄到了门店自己。

数据变多会分页吗？看 run 返回的 data.layout：page_count、x_pages、y_pages。本样例 13 行 1 页；明细变多先看 y_pages，列变多看 x_pages。

占比合计一定是 100% 吗？是。E5 的分子分母是同一个集合，恒等于 1——这是免费的自校验，若它不是 100%，说明合计行的条件写错了。

为什么不用 Excel？Excel 当然能做。区别在复现与验证：这份定义是纯文本，进 git、能 diff；run 留痕源码修订与输入指纹；四项断言随样例发布。定义即代码的全部逻辑见《报表定义即代码：JSON 定义 + CLI + Agent》；同一批机制落在 7 份真实业务报表上的拆解见《7 份业务报表，逐格拆解》。
