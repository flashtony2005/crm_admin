一、为什么要做：三层缺陷是串起来的

① 一张价格表只有一列 → 页面承诺与扣款不一致

tiers 原先只有 stripe_price_id 一列，月付与年付共用同一个 Stripe Price。 会员页写着「¥180 / 年」，Checkout 却拿同一个 Price 建订阅会话 —— 实际按月扣款。 当时的处置是**明确拒绝年付**（400 + 指到人工开通）：宁可少一条通路，也不能按错的周期收钱。 代价是年付只能人工收款。根因不在代码，在数据模型：Stripe 的一个 Price 天生绑定唯一计费周期。

② 更严重的一条：真实扣款之后不发货

apply_stripe_event 处理 checkout.session.completed 时， 只做 UPDATE members SET status = 1, stripe_customer_id = …， 把「周期落到 plan 上」推给尚未落地的订阅状态机（阶段 1）。
后果：用户真实付了钱，plan 仍是 free、到期时间为空。而且 Stripe 那条线上没有 orders 记录， 归因收入 / 对账 / 后台订单列表全都看不到这笔钱。在真实收款链路上等一个未来模块，等于持续资损。

本次把它补齐：会话 metadata 里带上 interval 与 tier_slug， Webhook 据此发货（月付 30 天 / 年付 365 天，套餐名落到 slug）。

③ 两个只有真截图才看得见的界面缺陷

现象根因为什么检查抓不到
周期切换的选中项不可见（用户以为自己还在月付） 类名写了 bg-os-text，而 index.css 里没有这个令牌 （只有 os-text-primary / os-text-muted），Tailwind v4 不报错、直接不生成样式 → 白字 + 无底色 = 白底白字 tsc / vitest / 构建全部通过；只有取浏览器计算样式才暴露
点「在线支付订阅」失败时页面毫无反应，用户反复点 失败信息写进了 err state，而那个内联错误位只在未登录表单里渲染 逻辑正确、类型正确，只是用户看不到

顺手做了一次全量令牌审计（10 个文件之外），另有两处同类失效：change-password.tsx 的 bg-os-bg、NewsletterWidget.tsx 的 bg-os-surface/60，一并修正。

四、四条硬规则（写进代码注释，防回归）

#规则违反的后果
1 年付只能取 stripe_price_yearly_id，缺价返回空串 → 400，绝不回落月价 页面写「¥180/年」、用户每月被扣一次 —— 不查 Stripe 账单看不出来
2 价格 / 天数 / metadata 必须由同一次 interval 解析派生 「按年价收 ¥180、只给 30 天」这类收款与契约不符，且订单里两个数字各自自洽
3 真实扣款的 Webhook 必须真发货（plan + 到期时间）；缺 metadata.tier_slug 时只激活账号、不凭空发会员 钱收了会员没发（本次修掉的资损点）；或反过来给未知套餐白送会员
4 发货失败返 5xx 让 Stripe 重投；但「会员不存在」这类终态返 200，不能返 Err 返 2xx 会永久丢事件；对终态返 Err 会让 Stripe 无限重投

六、当前站点实际状态与未决

站长还需做的两件事（否则在线支付按钮会如实显示「未配置」并禁用，人工开通不受影响）：

  • 后台「付费订阅 → 编辑套餐」填 月付 / 年付两个 Stripe Price ID（库里 monthly / annual 两条现在都还是空）；
  • 服务器配 STRIPE_SECRET_KEY 与 STRIPE_WEBHOOK_SECRET（未配时在线通道是硬拒绝，这是 P0-2 的既定行为）。

未决（阶段 1 订阅状态机）：本次只发「首个计费周期」（月 30 / 年 365 天）。 Stripe 的续费事件（invoice.payment_succeeded 等）仍落库标 pending_apply，不重复发货 —— 也就是年付会员在第 366 天需要状态机接手长订阅。 这是已知缺口，不是本次回归。
