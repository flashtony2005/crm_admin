从一张空表开始：手录 10 家门店数据，一步步做出组内排名报表

这次不用样例：数据是我自己敲的

画廊里那张「门店销售 · 组内排名与组内占比」可以直接跑（那次用样例数据的复现过程），但用的还是仓库自带的数据。真实场景是相反的：数据在自己手里，从一张空表开始。所以这篇文章换一条路——我从键盘敲了 10 家门店的销售数据，从零走完「录数据 → 证数据 → 写模板 → 过闸 → 交付」，每一步都是 agent 真执行过的，命令和输出照抄就能复现。

全程只用到两个东西：一个 CLI（rpx 0.16.0），一个验证脚本（skill 自带的 verify_report.py）。没有服务、没有登录、没有网络。

第 1 步 目录与 CSV：到底录了什么

先建一个只放两样东西的目录：一份数据、一份模板。数据放 data/ 子目录，模板放根上。

rpx-agent-store/
├─ data/
│   └─ store-sales.csv        ← 我手录的 10 行数据
├─ data-check.json            ← 探针模板（第 2 步用，1 个格子）
└─ template.json              ← 正式模板（第 5 步写）

CSV 全文 11 行（表头 + 10 家店），三个字段，一个多余的空格都没有：

region,store,amount

录的时候有四条硬规矩，违反了不会报错，只会静默算错：

规矩写错会怎样
逗号分隔，不能是制表符或分号列名不会被切开，整行变成一个字段名；到 run 才报 UnknownCell，且不告诉你是分隔符问题
表头用英文列名（region / store / amount）表达式里要按列名取值，中文列名也能用，但引号和转义更容易出错
金额只写数字，不写千分位、不写「元」214,000 会被当字符串，或被逗号切成两列；214000 元 直接算不了
存无 BOM 的 UTF-8带 BOM 时首列名会变成 \ufeffregion，表达式里写 region 就取不到值

这 10 家店故意做成三个大区、门店数不等（4 / 4 / 2）。等长分组最容易掩盖错误——组内排名和组内占比如果写错成全体口径，每组数量一样时看不出破绽；不等长才能暴露问题。

大区门店数销售额小计组内最高
华南4520,000深圳南山 214,000
华东4687,000上海浦东 268,000
华北2346,000北京海淀 241,000

第 2 步 先证数据，再碰版式

这一步是整条流程里最容易被跳过、也最容易省出几小时的一步。数据没被证实能加载之前，一个业务单元格都不要写。

先用一个「什么都不做」的探针模板：1 行 1 列，只有一个格子和一条数据集声明。

    {
      "name": "sales",
      "file": { "file_name": "store-sales.csv", "encoding": "UTF-8",

    }

然后只跑一条命令看数据：

columns: ['region', 'store', 'amount']
rows: 10
sample:

输出里三件事必须同时成立，缺一条就停手：

判据本次实测不成立说明什么
columns 是真正的列名列表['region','store','amount']若是一整串 ['region,store,amount']，就是分隔符没生效

第 4 步 模板是哪个：三个来源，我选了手写

「模板」在 rpx 里就是一份 JSON，不需要从空白写起。三个来源，各有适用场景：

来源命令能不能直接用
内置示例（5 份）rpx template create --example grouped-sales --out-dir .最接近。grouped-sales 就是「区域 → 城市两级 + 组内排名 + 图表」，第 4 列已是 count(C3[A3]{C3>$C3})+1
目录库预制（5 份）rpx library init ./reports --presets写入 complex-master / grouped-sales / multi-column / chart-gallery / images 五份，带 manifest 与修订号，适合当长期资产
画廊定稿（examples/r-model）不是 catalog 内建示例--example store-ranking 会直接报 EXAMPLE_UNKNOWN（stage: catalog）。它是仓库里的例子文件，只能拷贝，不能 create
手写最小骨架自己写 6 个格子先跑通本次选它：只要 6 列、不要图表，改示例反而要删东西

顺手把 grouped-sales 跑了一遍确认它的口径：华东 40/30/20 得到排名 1/2/3、华南 60/25/15 得到 1/2/3，确实是组内排名。它用的是 [A3] 局部坐标限定分组；画廊定稿用的是 [`0] 根坐标 + 条件收窄。两条都通，前者更短，后者更好解释「为什么是同一大区」。

第 5 步 模板长什么样：一格一格说清楚

画布是 6 行 × 6 列：第 1 行标题、第 2 行说明、第 3 行表头、第 4 行明细（会纵向扩展）、第 5 行合计、第 6 行脚注。

列宽不是随手写的，按内容定：

列内容宽度为什么
A大区14mm两个字加留白
B门店20mm四个汉字放得下，不折行
C销售额18mm#,##0 到 7 位数不出现 ####
D组内排名13mm只放一位数
E组内占比20mm0.00% 需要 ≥18mm，留 2mm 余量
F组内第一16mm放得下「★ 组内第一」

合计 101mm，A4 可用宽度约 172mm，很宽松——宽松是有意的：宽度不够会横向分页，或让窄列显示 ####，这两种都不报错。

七个功能格，每个都只回答一个问题：

格角色表达式它在干什么
A4纵向扩展sales.group(region)按大区去重，一个区一行，是整块的根
B4纵向扩展sales.select(store)，left_head=A4挂在大区下面列门店，父格指定 A4，形成父子链
C4不扩展sales.select(amount)，left_head=B4跟着门店走，取当前门店的金额
D4计算列count(C4[`0]{C4>$C4 and A4==$A4})+1全表里同大区、金额比我大的门店数 + 1
E4计算列C4/sum(C4[`0]{A4==$A4})我的金额 ÷ 同大区合计
F4计算列if(D4==1,'★ 组内第一','')排名第一打个标，其余留空
C5合计sum(C4[`0]{})整根格集求和，回到全体

D4 和 E4 里那个 [`0] 是根坐标（这套集合语义的完整拆解见格集与扩展块）：它把集合从「当前组的这几行」换成「全表所有明细行」。没有它，C4{} 的共同主格会收窄到门店自己，8 家店会全变成第 1 名。有了它之后，再用 A4==$A4 收窄到同一大区——这两件事是分开的，一个给全集，一个给范围。

$A4 的美元符号是「当前行」，A4==$A4 意思是「这一行的 A 列值 = 我这一行的 A 列值」，也就是同大区。这是全篇最容易写错的一处。

三个细节容易被忽略：没有声明任何 border——这个版本的边框不落地，快照和 xlsx 都不带，分层只能靠 back_color；合计行紧贴明细行，中间不能插空行，否则空行会被算进扩展块；F4 用了单引号字符串，双引号在 JSON 里要转义，单引号更省事。

第 6 步 三道静态关，一条命令跑完

$ rpx lint template.json --data-dir data
{"ok":true,"data":{"gate":{"exit_code":0,"passed":true},
 "summary":{"codes":[],"error":0,"warning":0,"total":0}}}

$ rpx template validate template.json --probe-data --data-dir data
{"valid":true,"probe":{"probed":true,"rows_total":10,
 "datasets":[{"name":"sales","columns_ok":true,"rows":10}]}}
checked:  schema / declared_heads / unconditional_scalar_cycles /
          formula_preparation / parameter_binding / inferred_heads
deferred: data_loading / calculation / pagination / export

三道关的分工必须分清，否则会误判「已经没问题了」：

关卡它到底证明什么它不证明什么
lint没有已知的静默失败写法（宏写错位置、多个纵向扩展未收敛、扩展块有空行、窄列配两位小数…）不证明能算出来
validate结构合法：6 项静态检查全过deferred 里明写 data_loading / calculation / pagination / export 都没查
validate --probe-data数据集真的能加载：列名对、行数对不证明公式算得对

所以看到 valid: true 就收工，是这个工具链上最贵的误判。本次 lint 0 告警，是因为列宽一开始就按 0.00% 需要 18mm 来定；画廊那份定稿模板反而是 13mm，跑 lint 会带 1 条 L008 告警。

    --export csv --export xlsx --export print-xlsx
{"ok":true,"data":{"layout":{"rows":15,"page_count":1,"x_pages":1,"y_pages":1}}}

run/artifacts/
├─ result.json          逐格结果（值 + 类型）

├─ report.csv           15 行纯值

模板只写了 6 行，结果 15 行：标题 1 + 说明 1 + 表头 1 + 明细 10 + 合计 1 + 脚注 1。这就是「扩展」——写 6 行，出 15 行，页数还是 1。layout 里同时给出 x_pages 和 y_pages，横向有没有分页一眼可见，不用去翻 workbook.json。

第 8 步 过闸：第一次是 FAIL

前三关全绿，也不代表能交付。唯一能证明「算对了」的是断言产物里的值，这件事由 skill 自带的 verify_report.py 一次做完：lint → validate → run（csv + xlsx + print-xlsx）→ 读 CSV 断言指定格。

第一次跑，直接 FAIL：

$ python verify_report.py template.json --data-dir data --expect-rows 15 --max-pages 1
[FAIL] template.json
  产物 0 个 | CSV None 行 | 分页 None
  ERROR R002 run 失败：DATA_MISSING
        F:\tmp\rpx-agent-store\store-sales.csv: 系统找不到指定的文件。
          → 看 run.json 的 diagnostics；数据集类错误先跑 dataset inspect

注意报错路径：rpx-agent-store\store-sales.csv——少了中间的 data\。也就是说 --data-dir data 传给了 lint，却没传给 run，脚本以为数据在模板同级目录。这不是我们的模板错，是验证脚本的一个真 bug。

修法只有两行（脚本里 run 的参数拼装处）：

run_args = ["run", tpl_path, "--out-dir", out_dir] + exports
if base:
    # 必须透传：数据放子目录（如 ./data/）时，run 默认只在模板同级找文件，
    # 否则会误报 DATA_MISSING
    run_args += ["--data-dir", base]

补上之后同一份模板、同一条命令：

[PASS] template.json
  产物 5 个 | CSV 15 行 | 分页 {'page_count': 1, 'x_pages': 1, 'y_pages': 1} | 边框定义 1
  无告警

还有两个坑，都是这次真踩的：--expect-cell 读的是 report.csv，所以坐标是结果坐标，不是模板坐标（模板里合计在 C5，结果里在 C14）；long / decimal 的值是字符串精确比对，写 0.3077 会 FAIL，必须写全精度 0.3076923076923077。

第 10 步 一个反直觉的地方：CSV 不带格式

report.csv 里读到的占比是 0.4115384615384615，不是 41.15%：

华南,深圳南山,214000,1,0.4115384615384615,★ 组内第一
华东,上海浦东,268000,1,0.3901018922852984,★ 组内第一

这不是 bug。format 只写进 workbook.json 和 xlsx，CSV 永远输出原始值。所以：

  • --expect-cell E13=0.30346820809248554 要写全精度，写 30.35% 一定不过；
  • 给人看的版本用 report.xlsx 或 report-print.xlsx，那里才是 41.15%；
  • 给下游程序用的用 CSV，格式化交给下游，别指望 CSV 帮你四舍五入。

换成你自己的数据，只改三处

这份模板不是为这 10 家店定制的，换数据只动三个地方：

改哪里改什么注意
CSV 文件名datasets[0].file.file_name文件名改了就同步改这里，否则 DATA_MISSING
列名表达式里的 group(region) / select(store) / select(amount)要和 CSV 表头逐字一致，大小写敏感
门店数文案B5 的「10 家门店」这是写死的文本格，不会自动变；写成 count(sales.select(store))&" 家门店" 也可以，但要确认字符串拼接语法

其余全部不动：排名和占比的口径是按列名绑定的语义，不按行数、不按门店名。加一个大区、加十家店，模板一行都不用改。

FAQ

为什么不用画廊那份现成的 JSON？ 因为它绑定了 8 家店的样例数据，而且它是仓库例子不是 catalog 示例（--example store-ranking 报 EXAMPLE_UNKNOWN）。更重要的是：抄一份别人的模板，你永远不知道自己哪一步写错了。从 6 个格子自己搭一遍，出问题时能定位到具体那一列。

一定要先写探针模板吗？ 不一定。但它只花 30 秒，能挡掉「跑到最后一步才发现列名是 \ufeffregion」这类事故。列名一旦错，validate 依然返回 valid: true，要到 run 才炸，而且报的是 UnknownCell——不会告诉你是编码问题。

排名遇到并列会怎样？ 这是竞赛排名：两家并列第 1，下一名直接第 3。因为公式是「比我大的个数 + 1」，两个相等的值互相都不大于对方，所以并列同名次、后面跳号。要改成顺序排名（1、2、3 不跳号）得换写法。

怎么确认「组内」而不是「全体」？ 两个信号：每组占比各自加到 100%；每组第一名的标记出现在三个不同大区。如果收窄失效，占比会变成占全体（三组加起来 100%，每组只有 30% 多），组内第一只剩一个。
